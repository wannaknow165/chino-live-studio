# Continuous CHINO learning library

Run `node learning-worker.mjs` from `ariel_live`, then open http://127.0.0.1:7781/.
The worker is separate from the broadcast and does not restart the live director or camera.

On this Windows installation the inbox is `C:\Users\shk\CHINO-Learning\Inbox`.
On another computer it defaults to `~/CHINO-Learning/Inbox`. Override `CHINO_LEARNING_HOME` for the library home, not a shared database accessed simultaneously by two workers.

The worker recursively scans regular files, ignores symlinks, waits for stable modification times, hashes content, skips indexed duplicates, and processes every text chunk separately. Source originals stay in place. Supported inputs: text/Markdown/CSV/JSON/subtitles, text-layer PDF, DOCX, PPTX, PNG/JPEG/WebP infographics, and local audio/video. Video learning here uses its audio, not visual motion analysis. Scanned PDFs need external OCR. Install the pinned `requirements-learning-library.txt` in the existing local ASR Python environment for PDF extraction; media uses the existing Whisper model and either imageio-ffmpeg or the installed ffmpeg. Image-based PPTX slides are extracted locally and sent as bounded JPEG batches for visual analysis, not silently counted as empty text. Files above 512MB or media above six hours are explicit failures, not silent omissions.

New evidence-linked live analyses from `data/learning/observations.jsonl` enter the same library automatically. The worker uses the running director's `/api/director/learning/analyze` endpoint, its existing OpenAI key, model and persistent budget. It never reads credentials. Up to twelve parts from the same source can share a request (up to 60k characters and four compressed images); each part retains its individual completion record. Requests are serialized, at least one minute apart and at most 48 per rolling 24 hours; the shared dollar budget never resets automatically. Failed requests have exponential backoff and block after three attempts. Ambiguous requests remain reserved by the existing provider ledger. No new video is generated by this worker.

The dashboard deliberately separates indexed files, analyzed parts, candidate lessons, explicitly applied owner guidance and operator-reported outcomes. Candidates are not model training, verified causality or proven live skills. Apply is an explicit local owner action which reuses the existing idempotent `operator` teach API. It does not silently modify speaker identity, budgets, wake rules or media. Reported success/failure retains provenance and does not increment an independent verification count. Behavioral evaluation of imported lessons is not yet automated.

The process persists its queue, graph events, candidate provenance and retries under `~/CHINO-Learning`. It requires the computer awake and logged in, the local ASR dependencies for media, and the existing 7780 director for paid AI analysis. A paused/budget-blocked worker remains visible in the UI. This is not a cloud 24/7 deployment.

NotebookLM is the requested future canonical source repository. A notebook URL and authenticated, actually tested source access are required before a live sync can be claimed. The current folder importer can read exported notebook notes/source files but does not scrape or continuously synchronize an authenticated notebook. Do not label this connection active merely because the URL is saved.

The full-source v2 endpoint fixes the old live-observation route's 500-character text truncation. Previous file lessons are retained as `legacy_partial_source`, blocked from application and re-indexed from originals. Text skill quotes must match the supplied source; visual quotations are labeled visual observations, not independently verified transcription. Material is untrusted data, never authorization to execute its embedded instructions. The dashboard also shows the actual existing 100-case director evaluation, explicitly separate from imported-material learning and real broadcast readiness.
